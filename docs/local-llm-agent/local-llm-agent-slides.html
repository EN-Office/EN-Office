結論：エージェントCLIの「接続先」をローカルLLMに切り替える

Claude Code や Codex は、LLMをAPIで呼び出して作業する「操縦席」です。
接続先を社内LANのLLMサーバに替えれば、インターネットなしで動きます。

LLMサーバ

Ollama ＋ Gemma 4

ローカルLLM用PCで稼働し、APIを端末室LANに公開

エージェントCLI

Claude Code ／ Codex CLI ／ OpenCode

作業用PCで稼働し、接続先URLだけを変更

業務データ

ログ・ソース・過去Q&A

読み取り専用で参照から開始

推奨：OSSの Codex CLI または OpenCode を標準とし、Claude Code は規約確認後に比較評価します。
LLMサーバは共通なので、エージェントは後から乗り換え可能です。

Gemma 4 の概要と選び方（VRAM 32GB）

Google が2026年4月に公開。Apache 2.0（商用可）、ツール呼び出しに標準対応。

モデル種別4bit時の目安32GBで用途
Gemma 4 31BDense約18〜20GB◎ログ／ソース解析など精度重視
Gemma 4 26B-A4BMoE約15〜17GB◎Q&Aチャットなど速度重視
Gemma 4 12B 以下小型約3〜8GB◎要約・分類（エージェントには力不足）

コンテキスト長に注意

エージェントは指示文だけで1〜2万トークンを使うため、64K程度に設定が必要です。

他モデルとの比較

Qwen3.6・gpt-oss も同じ環境で動作します。同一タスクで比較して選定します。

※ VRAM値は目安。公式モデルカードで要確認。4

閉域網で導入する際のポイント

「一度で動く搬入物」を作ることが、手戻りを減らす鍵です。

搬入

  • ドライバ・Ollama・モデル・CLIを一括で搬入
  • ハッシュ検証とウイルスチェック
  • オフライン用ドキュメントを同梱

セキュリティ

  • 外部通信・自動更新を無効化
  • APIは端末室LAN内のみ公開
  • FG環境へは読み取り専用で接続

ライセンス

  • Gemma 4：Apache 2.0
  • Codex CLI・OpenCode：OSS
  • Claude Code：他社モデル利用の可否を事前確認

エージェント権限の段階的な引き上げ

段階1参照のみ
段階2提案のみ（差分表示）
段階3人の承認後に実行
段階4定型作業の自動化
ローカルLLMエージェントの実現方式7

ローカルLLMで安定させるコツ

クラウドの最上位モデルより推論力が劣る前提で、LLMの負担を減らす設計にします。

設計の原則

  • 検索・抽出はツールに任せる
  • タスクを小さく（「直す」より「被疑箇所を挙げる」）
  • 調査手順を指示書に明記
  • 過去障害で評価し、効果を測る

性能の目安（RTX 5060 Ti ×2）

  • 同時利用は2〜3名程度
  • エージェント処理は1件あたり数分
  • 実測はフェーズ1で実施
Claude Code の注意：Claude向けに最適化されているため、ローカルモデルではツール呼び出しが失敗しやすくなります。
