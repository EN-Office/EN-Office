# UX基礎設計

前提：方向性は D案「経営シムの骨格 × 企業擬人化モンスター育成」（ADR-0001, accepted）。
プラットフォームは iOS / Android のネイティブアプリ（スマートフォン縦持ちを基本）。モックアップはブラウザで動くHTMLプロトタイプで作る（ADR-0002）。
ターゲットは20〜50代のシミュレーション・街づくりゲーム好き（M&Aの予備知識なし）。

## 1. 体験の構造（3層ループ）

| 層 | 時間 | 内容 | プレイヤーの目的 |
|---|---|---|---|
| **マイクロ** | 30秒〜2分 | 1つの判断（どこをDDで調べるか、どの条項を入れるか） | 正しい判断を選ぶ |
| **コア（1案件）** | 10〜15分 | 探索 → 鑑定 → 交渉 → DD → 契約 → 統合 → 振り返り | 案件を成功させる |
| **メタ** | 数日〜数週間 | 街（グループの拠点）の発展、章の進行、ランク昇格、図鑑収集 | 自分の街と企業グループを大きくする |

## 2. コアループ（1案件の流れ）

```
 ┌──────────────────────────────────────────────────────────┐
 │ ① 探索      ② 鑑定        ③ 交渉       ④ DD          │
 │ Sourcing → Valuation → LOI/交渉 → Due Diligence ─┐   │
 │                                                    ↓   │
 │ ⑦ 振り返り ← ⑥ 統合(PMI) ← ⑤ 契約・クロージング ←──┘   │
 │ Debrief      100日プラン     SPA・表明保証              │
 └──────────────────────────────────────────────────────────┘
          ↓ 成果がグループ企業価値・ランク・図鑑に反映
```

| # | フェーズ | プレイヤーの行動 | ゲームメカニクス | 失敗した時に起きること |
|---|---|---|---|---|
| ① | 探索（ソーシング） | 自社の戦略（例：販路を広げたい）に合う企業獣を探す | マーケットマップで候補を発見。仲介者・FAから紹介を受ける | 戦略に合わない企業を買うとシナジーが出ない |
| ② | 鑑定（バリュエーション） | 企業価値を算定する | 3つの“鑑定レンズ”（純資産法／類似会社比較／DCF）で価値レンジを出す | 高値掴み → 後で減損 |
| ③ | 交渉（意向表明・基本合意） | 価格・スキーム・条件を提示する | 売り手の「本当の動機」（後継者不在、資金難、従業員の雇用）を会話から読む。競合入札者と競う | 決裂、または不利な条件 |
| ④ | DD（デューデリジェンス） | 限られた予算と日数で調査する | 調査ボード：財務・法務・税務・ビジネス・人事のどこに調査ポイントを割り振るか。**隠しステータス**（簿外債務、訴訟、キーマン依存等）が判明 | リスクを見逃すと契約後に発覚 |
| ⑤ | 契約・クロージング | DDで見つけたリスクを契約で手当てする | 条項カード（価格調整、表明保証、補償、クロージング条件）をはめ込むパズル | 補償を入れ忘れるとリスクを自社が負う |
| ⑥ | 統合（PMI） | 100日プランを実行する | 企業獣の「なつき度（従業員エンゲージメント）」と既存の仲間との「相性（文化）」を管理しながら、シナジー施策を選択 | 人材流出・顧客離反・シナジー未達 |
| ⑦ | 振り返り（デブリーフ） | 結果と判断の因果を確認する | タイムラインで「どの判断が結果に効いたか」を表示。用語カードを獲得 | （学びの言語化の場） |

**設計原則**
- **判断 → 結果の因果を必ず見せる**：振り返りで「③で売り手の動機を読み違えた → 価格が上がった → ⑥で減損」のように因果をつなぐ。
- **正解は1つではない**：リスクを取って安く買う／高くても確実に買う、などの戦略差を許容する。
- **用語は使う瞬間に教える**：用語は初出時にツールチップで説明し、図鑑（用語辞典）に自動登録する。
- **失敗を安全にする**：案件はやり直し可能。失敗した案件ほど振り返りで多くの学びが得られる設計にする。

## 3. 企業獣（カンパニー・ビースト）の設計

| ゲーム上の要素 | 実際の意味 | 表現 |
|---|---|---|
| 種族・属性 | 業種（IT、製造、小売、医療、物流…） | 姿・色 |
| 体格 | 売上高 | 大きさ |
| 攻撃力 | 営業利益・利益率 | 爪・牙など |
| 守備力 | 純資産・自己資本比率 | 甲羅・鎧 |
| スタミナ | 手元資金（キャッシュ） | ゲージ |
| 重り | 有利子負債 | 鎖・荷物 |
| 成長力 | 売上成長率 | 若さ・成長段階 |
| 特性（スキル） | 技術、ブランド、顧客基盤、人材、許認可 | スキルアイコン（＝シナジー源） |
| 隠しステータス | 簿外債務、訴訟、税務リスク、キーマン依存、労務問題 | DDで「？」が開示される |
| なつき度 | 従業員エンゲージメント | 表情・ハート |
| 相性 | 企業文化の近さ | 統合時の反応 |

- 財務データは簡易的な財務三表（PL/BS/CF）として**いつでも“本当の数字”を見られる**ようにする（擬人化は入口、数字が正）。

## 5. 進行設計（章立てと学習段階）

| 章 | テーマ | 案件の例（架空） | 新しく学ぶこと | 解放される機能 |
|---|---|---|---|---|
| 序章 | チュートリアル | 小さなパン屋の事業承継 | M&Aとは、株式譲渡、全体の流れ | 基本ループ（簡易版） |
| 1章 | 事業承継M&A | 後継者のいない町工場 | 純資産法、財務DD、表明保証 | 鑑定レンズ①、DD（財務） |
| 2章 | 成長のための買収 | 販路を持つ地方小売チェーン | 類似会社比較、シナジー、PMIの基礎 | 鑑定レンズ②、PMIボード |
| 3章 | 競争入札 | 人気のSaaS企業 | DCF、入札プロセス、勝者の呪い | 鑑定レンズ③、入札 |
| 4章 | 失敗から学ぶ | 過去に高値で買った子会社 | のれん・減損、統合失敗の典型 | 振り返り（応用） |
| 5章 | スキームを選ぶ | 一部事業だけ欲しい案件 | 事業譲渡・会社分割・株式交換、税務の基礎 | スキーム選択 |
| 6章 | 大型案件 | 上場企業の買収 | LBO、TOB、MBO | 資金調達 |
| 7章 | 敵対的買収と防衛 | ライバルファンドの攻勢 | 敵対的買収、ホワイトナイト、買収防衛策 | 防衛イベント |

- 各章は「新しい概念を1〜3個だけ追加」し、前章までの概念を組み合わせて使わせる。
- 章末に理解度チェック（3〜5問）を置き、学習効果を測る。

## 6. メタ進行

- **ランク**：アナリスト → アソシエイト → VP → ディレクター → MD（マネージングディレクター）。ランクで扱える案件の規模が上がる。
- **街の発展（メタ進行の主役）**：買収した企業獣は街に「拠点（建物・区画）」として加わる。シナジーが出た企業同士を隣に配置すると効果が上がる、統合がうまくいくと建物がグレードアップする、など、街づくりの楽しさとM&Aの成果を連動させる。
  - 配置の自由度は「カジュアル街づくり」程度に抑え、道路や電力のような管理の手間は入れない。
- **グループ企業価値**：全案件の成果を合算したスコア。街の規模や景観に反映される。
- **図鑑**：出会った企業獣、獲得した用語カード、ケースを収集。
- **フリープレイ**：章クリア後、ランダム生成の案件で反復練習。

## 7. オンボーディング方針

- 最初の3分で「企業獣を1体迎え入れる」体験を完了させる（序章は大幅に簡略化）。
- 専門用語は序章では最大5語まで。
- 「財務諸表が読めない人」でもクリアできる難易度を序章〜1章の基準にする。
- 序章のゴールは「最初の企業獣を迎え入れ、街に最初の建物が建つ」こと。M&Aの説明より先に、遊びの気持ちよさを体験させる。
