# UIガイドライン（モックアップ）

## 1. 目的
モックアップ全画面で、見た目と操作感を揃えるための規則を決める。画面を作る・直すときは必ずこの文書に従う。
出発点は Yu の指示（2026-11-11）：文字を減らす／簡単な用語にモーダルを出さない／押せるものと押せないものを明確に分ける／可能ならサウンドとGLBの3D表現。

## 2. 前提
- 画面は縦9:16のステージ内。サイズは `cqw` と `em` で指定し、px固定にしない。
- 世界観は「夕暮れのマーケット大陸」。色は `css/app.css` の `:root` 変数だけを使う（新しい色を画面側で作らない）。
- 書体：見出し `--font-display`、本文 `--font-body`、数値 `--font-data`。

## 3. 本文

### 3.1 押せる・押せないの区別（最重要）
原則は **「押せるものは立体、押せないものは平面」**。例外を作らない。

| 種類 | クラス | 見た目 | 用途 |
|---|---|---|---|
| 主ボタン | `.btn` | 琥珀の塗り＋下端に濃い段差。押すと沈む | 画面を先へ進める操作。1画面に1つ |
| 副ボタン | `.btn.sub` | 中立色の塗り＋下端に段差 | 戻る、閉じる、もう一度 |
| 選択カード | `.tap` | 中立色の塗り＋下端に段差。選択中は `.on`（琥珀の枠＋右上に✓）、不正解は `.ng` | 候補・選択肢・マス目などすべての選べる要素 |
| 丸ボタン | `.ibtn` | 丸い塗り＋下端に段差 | 戻る矢印、音のオン・オフ |
| 用語ボタン | `.q` | 小さな丸い「？」。段差つき | 専門用語の説明を開く |
| 情報パネル | `.panel` | 平面。枠線なし・影なし・薄い地色 | 数値や説明など、押せない情報のまとまり |
| ラベル | `.chip` | 平面の小さな札 | 状態・属性の表示 |

- 押せる要素は必ず `<button>`。押せない要素に枠線・影・ホバー変化をつけない。
- 無効（`disabled`）は段差を消して平面の灰色にする。「押せそうに見えるが押せない」状態を作らない。
- 押せる要素はすべて、押した瞬間に沈む動き（`:active`）と音（3.3）で反応する。
- タップ領域は最小 11cqw 四方。
- 街の3D画面：押せるのは建物・コイン吹き出し・配置マス・クエスト札・下部ナビ。所持コインなどのHUDは平面にする。初回だけ指アイコン（👆）で押す場所を示す。

### 3.2 文字量
- 1画面1メッセージ。ミナトの吹き出しは1文・全角24字以内。段落の説明文は置かない。
- 項目の説明文は、アイコンつきの短い札（`.chip`、1項目2つまで、各6字以内）に置き換える。
- ボタンの文言はアイコン＋8字以内。
- 遊び方の説明は「アイコン＋短い語」の3ステップで示す。
- 数値は大きく、単位は小さく。
- 学習内容を削りすぎない。判断の理由（なぜ正解・不正解か）は1行で必ず残す。

### 3.3 用語モーダル
- 「？」ボタンと用語モーダルを出すのは、次の専門用語だけにする：デューデリジェンス（DD）、純資産法、含み益、基本合意書（MOU）、株式譲渡契約（SPA）、表明保証、価格調整、クロージング条件、キーマン条項、簿外債務、100日プラン（PMI）、シナジー、のれん、TOB。
- M&A、資産、負債、探索、鑑定、統合、後継者、アドバイザー、企業獣、なつき度などの平易な語には「？」もモーダルも出さない。
- 同じ画面で同じ用語の「？」は1回だけ。本文に点線の下線は引かない。
- 用語の定義は `docs/glossary.md` と一致させる。

### 3.4 サウンド
- 音声ファイルは使わず、Web Audio の合成音で鳴らす（`js/audio.js`）。最初の操作のあとから鳴る。
- `SFX.play(name)` の種類：`tap`（通常の押下）、`select`（選択）、`ok`（正解・確定）、`ng`（不正解・不可）、`coin`（回収）、`up`（アップグレード）、`place`（配置）、`open`／`close`（モーダル）、`step`（次のステップへ）、`win`（成功の演出）、`start`（開始）。
- すべての `<button>` は押すと自動で `tap` が鳴る。別の音にしたいボタンには `data-sfx="名前"`、鳴らしたくないボタンには `data-sfx="none"` をつける。
- 画面右上の丸ボタン（🔊／🔇）でいつでも消音できる。設定は端末に保存する。
- 音は短く控えめに。同時に鳴らしすぎない。

### 3.5 3D表現（GLB）
- モデルは Blender のスクリプト（`tools/blender/build_models.py`）で生成し、`mockup/assets/models/*.glb` に置く。ダブルクリックで開いても動くよう、同じ内容を `mockup/assets/models.js` に埋め込む。
- 形はローポリで丸みのある玩具風。色は 3.1 と同じパレット。1モデル150KB以下を目安にする。
- 街の画面（中心画面）は three.js の3Dで描く。建物と企業獣はGLB、コイン吹き出しやHUDはHTMLを重ねる。
- 主役として大きく見せる企業獣は `data-beast3d="キー"` をつけると3D表示になる。3Dが使えない環境では、中のSVGがそのまま表示される。
- 3D表示は1画面4つまで。一覧の小さなアイコンはSVGのままにする。
- `prefers-reduced-motion` のときは自動回転と揺れを止める。

### 3.6 動き
- 画面の切り替えは0.3〜0.45秒のフェード。押下の反応は0.1秒以内。
- 成功の演出（回収、アップグレード、M&A成功）は「動き＋音＋数値の変化」を同時に出す。
